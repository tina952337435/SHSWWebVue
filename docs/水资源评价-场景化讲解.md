# 水资源评价 · 设计讲解稿（产品汇报版）

> 定位：这是根据我们自己的理解做出的设计稿，讲给客户听，目标是让对方看懂设计思路并提出修改意见，不是最终方案。
> 讲法：每块按「为什么做 → 怎么设计 → 演示什么 → 请客户确认什么」四步走，不背功能清单。

---

## 开场（定调，30 秒）

"今天汇报的是水资源评价模块的设计稿。这些页面是我们根据前期对业务的理解先做出来的，目的是把功能思路和交互方式摆出来，和大家对齐；具体指标、数据来源和细节，会后按大家的意见再调整。"

主线一句话："从一张图看现状，到算清进出水量，再看水质和生态，最后形成月报。"

---

## 1. 主要断面流量实时感知

- **为什么做**：先解决"全市水情在哪看"的问题，这个页面是整个模块的入口。
- **怎么设计**：默认只放地图，断面和流向箭头一眼看清；明细表收到右侧，需要时再拉出来——一上来就给表格，信息太满。
- **演示**：指地图讲流向（咸潮期箭头会反）；悬停松浦大桥看实时数据；拉出明细看统计和筛选；按片区筛一次。
- **请确认**：断面选取范围是否合适？默认要展示哪几个指标（流量 / 水位 / 警戒）？

## 2. 历年水资源量查询

- **为什么做**：判断今年是丰是枯，需要多年数据做参照。
- **怎么设计**：一次只看一个指标，避免多指标挤在一张图上；柱子上加多年平均线，高低一眼可比。
- **演示**：切换三个指标；看平均线；切页签看不同维度。
- **请确认**：年份范围、维度划分、多年平均的口径，是否按现有年报来？

## 3. 出入境水资源量计算

- **为什么做**：回答"上海一年从外面进来多少水、又出去多少水"。
- **怎么设计**：左侧按边界分组选断面，右侧净水量 = 出 − 入，柱状图正负一眼分辨；粒度可切日 / 旬 / 月 / 年。
- **演示**：默认两个断面 → 看全年 → 切到月，讲"只改粒度、不改时间区间"。
- **请确认**：边界断面清单是否完整？净水量是按站求和，还是先汇总再相减？

## 4. 省市边界污染物通量分析

- **为什么做**：光看水量不够，还要看水质，通量把"水量 × 浓度"合成一个可比的量。
- **怎么设计**：单指标看总量构成，出、入两张饼图分开；多指标看单个断面的因子随时间怎么变；表格明确分出 / 入，不留歧义。
- **演示**：切一个因子；对比两张饼图；切多指标看轮换和过程线。
- **请确认**：因子清单和分组方式？出 / 入比例的正式口径怎么定？

## 5. 生态流量监测预警

- **为什么做**：河湖生态用水有没有被挤占，需要持续盯着，不能等出问题再查。
- **怎么设计**：总览看今天谁不达标；统计看一段时间的趋势；记录看历史；规则让业务人员自己调阈值，不用改代码。
- **演示**：总览 → 点一个断面看统计 → 现场改一条规则。
- **请确认**：考核断面范围？目标值从哪来？预警分级按什么标准？

## 6. 生态流量月报

- **为什么做**：监测结果最终要形成能上报、能存档的月报。
- **怎么设计**：选月份一键生成四段式报告，可预览、下载、存档；月报管理统一查历史。
- **演示**：生成 → 预览 → 下载。
- **请确认**：报告模板和四段结构，是否符合公文要求？

## 三条现场原则

1. **先说为什么，再讲怎么做**：每个功能开口先讲业务问题，客户才听得进设计。
2. **不纠结数据真假**：被问到就说"演示数据，正式版接实时数据"，不要把时间花在解释数值上。
3. **客户提意见先记下**：不当场争对错，回一句"这个记下来，会后按您的意见调整"，把会议目标守住。
